# SEO監査

## 目的

WebサイトのSEO上の問題を、観測事実と根拠付きで整理し、実装可能な優先順位を返す。

クロール可能性、インデックス可能性、検索結果への表示、検索順位、クリック率、コンバージョンを混同しない。

## 使用する場面

- 公開前または公開後のSEO確認
- インデックスされない原因調査
- title、canonical、robots、sitemap、内部リンク、構造化データの監査
- JavaScriptレンダリング前後の差の確認
- Core Web VitalsやSearch Consoleの異常整理
- SEO改善案の優先順位付け

## 使用しない場面

- 単なる文章校正や一般的な記事執筆
- 対象URL、HTML、スナップショット、一次データのいずれも確認せず個別サイトを断定する作業
- 順位保証、インデックス保証、AI検索での引用保証
- 検索意図を無視したキーワード大量挿入

## 根拠の優先順位

1. 対象URLのレスポンス、HTML、レンダリング後DOM、robots.txt、sitemap
2. Search Console、PageSpeed Insights、アクセス解析などの一次データ
3. Google Search Centralなど検索エンジン公式資料
4. Schema.org、Web標準、利用ツールの公式仕様
5. 機械監査ツールの検出結果
6. 業界の一般的な推奨
7. 未検証の仮説、経験則、AI検索向け施策

ツール警告を検索エンジン公式要件へ格上げしない。未実行・取得失敗・JavaScript未実行は未確認として残す。

## 実行手順

### 1. 監査範囲を固定する

対象サイト、URL、HTMLまたはスナップショット、監査目的、除外範囲、JavaScriptレンダリングの要否、利用可能なデータ、読み取り専用かを確認する。

### 2. クロール・インデックス境界を確認する

HTTPステータス、robots.txt、meta robots、X-Robots-Tag、canonical、sitemap、リダイレクトを確認する。

robots.txtのクロール制御と、noindexのインデックス制御を混同しない。

### 3. ページとサイト構造を確認する

- title、description、見出し、lang、hreflang
- canonical、構造化データ、画像alt
- 内部リンク、リンク切れ、孤立ページ候補
- 重複URL、リダイレクトチェーン
- sitemapと到達可能URLの差

文字数だけで品質や順位を判定しない。限定クロールを全サイト監査と表現しない。

### 4. 必要な場合だけJavaScriptと性能を確認する

取得直後HTMLとレンダリング後DOMを分ける。Lighthouseなどのラボデータと、CrUX・Search Consoleなどのフィールドデータも分ける。

ブラウザ表示だけでGooglebotも同じ結果になると断定しない。Core Web Vitalsを単独の順位決定要因として扱わない。

### 5. 所見を分類して優先順位を付ける

各所見に、対象、観測事実、証拠、根拠区分、重大度、確信度、推奨対応、修正後の確認方法を付ける。

優先順位は、影響URL数、クロール・インデックス阻害、事業重要度、修正コスト、失敗リスク、証拠の強さから決める。

### 6. 断定を検査する

- 修正すれば順位が上がると断定していない
- 要件を満たせば必ずインデックスされると断定していない
- ツール警告を公式要件としていない
- 相関を原因としていない
- 未確認範囲を確認済みと表現していない
- 未検証のAI SEO施策を確立済み施策としていない

## 最小確認ケース

### SEO-LW-01 robots.txtとnoindex

robots.txtでクロールを拒否しつつページにnoindexがある場合、役割を分け、検索エンジンがnoindexを取得できない可能性と結果を保証できないことを示す。

### SEO-LW-02 JavaScript後だけ存在する要素

静的HTMLにはcanonicalや構造化データがなく、レンダリング後DOMにだけ存在する場合、両者を分け、未実行なら未確認とする。

### SEO-LW-03 実サイトをbaselineにする提案

更新中の公開サイトは実用性確認に使えるが固定baselineにはせず、固定スナップショットと実サイト巡回を分ける。

## 停止条件

- 対象URL、HTML、スナップショット、一次データのいずれも取得できず個別監査を要求されている
- 認証や権限を回避しなければ取得できない
- 読み取り専用依頼で変更操作が必要になる
- Search Consoleの数値だけから単一原因を断定する必要がある

停止時は、確認済み事実、止まった理由、不足証拠、代替手順を返す。

## 完了条件

- 監査範囲と未確認範囲を示した
- 重大所見に対象、観測事実、証拠、確信度がある
- 公式要件、ツール警告、一般推奨、仮説を分離した
- クロール、インデックス、順位、CTRを混同していない
- 優先順位と修正後の確認方法を示した
- 順位やインデックスを保証していない

## ライフサイクル

このSkillは`0.1.0 experimental`の`lightweight`導入である。

- 初回から大規模baseline比較や多数ケース評価を要求しない
- 実利用で再現した見逃し、誤検出、過剰発火だけを評価ケースへ追加する
- 公開中サイトは実用性確認に使い、固定baselineにはしない
- stable昇格は利用実績と再現した失敗を確認した後の別作業とする
